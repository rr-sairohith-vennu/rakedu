Setup Do this first

Get the App Running

The app is pre-built with seeded cashback events. Clone it, install, and start the dev server.

Terminal
git clone https://github.com/rr-sairohith-vennu/rakcal cd rakcal git checkout workshop-start npm install npm run dev
Open http://localhost:3000 — you should see the Cashback Calendar with events.

Install Playwright MCP — needed for forge:build-playwright-tests:

Terminal
claude mcp add playwright -- npx @playwright/mcp@latest
Restart Claude Code after running this. Then open the rakcal folder in Claude Code and continue.

When Claude Code asks for permission to run a bash command — answer Yes (and don't ask again).

What to look for
Which BRs have no test scenario

forge:spec-tests uses these gaps to generate scenarios. Reading the report helps you judge whether the output is complete.
Step 1 forge:spec-tests — ~5 min

Generate BDD Test Scenarios

Reads requirements and generates numbered BDD scenarios. No test code yet — this is the specification layer.

0.5 Gap →1 spec-tests →2 build-tests →3 spec-ui-e2e →4 build-playwright →5 fix + run
Claude Code
/forge:spec-tests --type e2e
Generates two files under .forge/efforts/cashback-calendar/spec/test/
e2e-test-suite.md — system/API scenarios (SC-1 through SC-13)
ui-e2e-test-suite.md — UI browser scenarios (SC-1 through SC-13)
When it finishes — ignore the "Next steps" suggestion. forge:spec-tests will suggest running forge:spec-ui-e2e directly. Skip that and follow this guide's order. Step 2 is forge:build-tests.
Step 2 forge:build-tests — ~8 min

Build API / E2E Test Code

Reads the BDD scenarios and implements the ones testable via HTTP (API routes + page rendering). Browser scenarios are handled in Step 4.

0.5 Gap →1 spec-tests →2 build-tests →3 spec-ui-e2e →4 build-playwright →5 fix + run
Claude Code
/forge:build-tests --type e2e-test
When it asks what to implement — choose Option 1 (axios HTTP tests for API routes and HTTP-testable page scenarios).

Output: tests/system/e2e/api/ — axios tests hitting localhost:3000
What it tests
GET /cashback-calendar/v1/events
GET /cashback-calendar/v1/events/:id
GET /cashback-calendar/v1/merchants
Page renders (SC-1, SC-3, SC-7, SC-9)
What it skips
Browser click interactions, modal open/close, keyboard events — those require Playwright (Step 4).
Step 3 forge:spec-ui-e2e — ~2 min

Generate Gherkin Feature Files

Converts ui-e2e-test-suite.md into Gherkin .feature files — the input format forge:build-playwright-tests reads to generate Playwright specs.

1 spec-tests →2 build-tests →3 spec-ui-e2e →4 build-playwright →5 fix + run
Claude Code
/forge:spec-ui-e2e
Answer the prompts
› Region → us
› Feature area → cashback-calendar
Output: features/us/cashback-calendar/
One .feature file per surface — calendar-view.feature, event-detail.feature, filters.feature
Open any .feature file — each scenario is Given / When / Then. This is exactly what forge:build-playwright-tests turns into Playwright code.
Step 4 forge:build-playwright-tests — ~15 min

Build Playwright UI Tests

Opens a real browser, discovers DOM selectors from the live app, writes .spec.ts files for each .feature file, runs them, and fixes failures.

2 build-tests →3 spec-ui-e2e →4 build-playwright →5 fix + run
Claude Code
/forge:build-playwright-tests us
First run only: Playwright MCP installs and asks you to restart Claude Code. After restarting, run the same command again — it continues from where it stopped.
Watch the browser open and interact with the calendar automatically — navigating months, clicking days, opening modals. This is the live DOM discovery phase.
Output: tests/bdd/cashback-calendar/
One .spec.ts per .feature file. Runs headless, fixes up to 3 cycles, then runs validate.js.
Step 5 Fix + Run

Fix Failures & Run in Headed Mode

Fix any remaining failures, then run with a visible browser so you can see every scenario play out.

3 spec-ui-e2e →4 build-playwright →5 fix + run

If any tests are still failing:

Fix failures
/forge:build-playwright-tests us --fix

Run all tests in headed slow mode:

Terminal
npx playwright test tests/bdd/cashback-calendar/ --project=local-anonymous --headed --slow-mo=800
Watch the browser: navigate months → click an event day → see merchant details → apply a filter. Each action maps to a BDD scenario from the feature files.
Help Troubleshooting

Common Problems

  • App not loading at localhost:3000 — npm run dev must be running in a separate terminal. Keep it open the entire time.
  • Playwright MCP not found — Run claude mcp add playwright -- npx @playwright/mcp@latest then restart Claude Code.
  • Permission prompts keep appearing — Choose "Yes (and don't ask again for this command)" each time.
  • forge:build-tests asks which scenarios to implement — Choose Option 1 (axios/HTTP tests). Browser scenarios go to forge:build-playwright-tests.
  • Tests fail after 3 fix cycles — Stop. Read the last error. Usually a selector changed or the server isn't running. Fix the root cause before re-running.
  • forge:spec-ui-e2e asks for region — Answer us, feature area cashback-calendar.
  • Context window filling up — Run /compact in Claude Code, then resume the skill.
  • Gap report path not found — Correct path: .forge/efforts/cashback-calendar/validation/report.md
