Get the App Running

The app is pre-built with a seeded database. Clone, install, and start — that's it.

Terminal — clone, install, and start
git clone https://github.com/rr-sairohith-vennu/rakcal cd rakcal git checkout workshop-start npm install npm run dev
Open http://localhost:3000 — you should see the Cashback Calendar with events on the grid. No DB setup needed.

Install Playwright MCP (needed for Step 4):

Terminal
claude mcp add playwright -- npx @playwright/mcp@latest
Restart Claude Code after this. Then open the rakcal folder in Claude Code and continue from here.

Step 1 forge:spec-tests — ~5 min

Generate BDD Scenarios

Reads the requirements and generates numbered BDD scenarios. No test code yet — this is the specification layer.

0.5 Gap →1 spec-tests →2 build-tests →3 spec-ui-e2e →4 build-playwright →5 fix + run
Claude Code
/forge:spec-tests --type e2e
Output → .forge/efforts/cashback-calendar/spec/test/
e2e-test-suite.md — system/API scenarios
ui-e2e-test-suite.md — UI browser scenarios
Open these files and read through the scenarios while the next steps run.
When it finishes, it suggests running forge:spec-ui-e2e next. Ignore that. Follow this guide — Step 2 is forge:build-tests.
Step 2 forge:build-tests — ~8 min

Build API & E2E Tests

Implements the HTTP-testable scenarios as axios tests hitting localhost:3000. Browser interaction scenarios are handled in Step 4.

0.5 Gap →1 spec-tests →2 build-tests →3 spec-ui-e2e →4 build-playwright →5 fix + run
Claude Code
/forge:build-tests --type e2e-test
When it asks what to implement
› Choose Option 1 — axios HTTP tests for API routes + HTTP-testable page scenarios
What it tests
GET /cashback-calendar/v1/events
GET /cashback-calendar/v1/events/:id
GET /cashback-calendar/v1/merchants
Page renders (SC-1, SC-3, SC-7, SC-9)
What it skips
Browser clicks, modal open/close, keyboard events — those need Playwright (Step 4).
Note: At the end it says "run with npm run test:e2e" — that's just a reminder for manual use. The skill already ran the tests. You don't need to run anything.
Step 3 forge:spec-ui-e2e — ~2 min

Generate Gherkin Feature Files

Converts ui-e2e-test-suite.md into Gherkin .feature files — the format forge:build-playwright-tests reads to write Playwright specs.

1 spec-tests →2 build-tests →3 spec-ui-e2e →4 build-playwright →5 fix + run
Claude Code
/forge:spec-ui-e2e
Answer the prompts
› Region → us
› Feature area → cashback-calendar
Output → features/us/cashback-calendar/
One .feature file per surface: calendar-view.feature, event-detail.feature, filters.feature
Open any .feature file — each scenario is Given / When / Then. This is exactly what forge:build-playwright-tests converts to Playwright code.
Step 4 forge:build-playwright-tests — ~15 min

Build Playwright UI Tests

Opens a real browser, discovers DOM selectors from the live app, writes .spec.ts files, runs them, and fixes failures automatically.

2 build-tests →3 spec-ui-e2e →4 build-playwright →5 fix + run
Claude Code
/forge:build-playwright-tests us
First run only: If Playwright MCP wasn't installed yet, it installs now and asks you to restart Claude Code. After restarting, run the same command again.
Watch the browser open and interact with the calendar automatically — navigating months, clicking event days, opening the detail modal. This is the live DOM discovery phase where it finds real selectors.
Output → tests/bdd/cashback-calendar/ — one .spec.ts per .feature file. Runs headless, fixes up to 3 cycles, then runs validate.js.
Step 5 Fix + Run

Fix Failures & Run Headed

If any tests are still failing, fix them. Then run with a visible browser so you can watch every scenario execute.

3 spec-ui-e2e →4 build-playwright →5 fix + run

If tests are still failing after Step 4:

Fix
/forge:build-playwright-tests us --fix

Run all tests headed with slow motion:

Terminal
npx playwright test tests/bdd/cashback-calendar/ --project=local-anonymous --headed --slow-mo=800
Watch the browser navigate months, click event days, open merchant details, apply filters — all driven by the BDD scenarios you generated in Step 1.
Help Troubleshooting

Common Problems

  • API returns HTML instead of JSON — Dev server not running. Make sure npm run dev is running in a separate terminal.
  • App not loading at localhost:3000 — npm run dev must be running in a separate terminal. Keep it open the entire time.
  • Playwright MCP not found — Run claude mcp add playwright -- npx @playwright/mcp@latest then restart Claude Code.
  • Permission prompts keep appearing — Choose "Yes (and don't ask again for this command)" each time.
  • forge:build-tests asks which option — Choose Option 1 (axios/HTTP). Browser scenarios go to forge:build-playwright-tests in Step 4.
  • "Run with npm run test:e2e" message — Informational only. The skill already ran the tests. You don't need to do anything.
  • Tests fail after 3 cycles — Read the last error carefully before re-running. Usually a selector changed or the server isn't running.
  • forge:spec-ui-e2e asks for region — Answer us, feature area cashback-calendar.
  • Context window filling up — Run /compact in Claude Code, then resume the skill.
