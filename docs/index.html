Cashback Calendar — Testing Flow

Follow these steps to run the full Forge testing pipeline on the Cashback Calendar feature. Each slide has the exact command to run and what to expect.

forge:spec-tests forge:plan forge:build-tests forge:spec-ui-e2e forge:build-playwright-tests
PRD: Cashback Calendar — Confluence
Repo: Clone the workshop-start branch — the app is pre-built and ready. You only run the testing skills.
Setup Before you start

Get the App Running

The Cashback Calendar app is already built. Clone it, install deps, start the server — then run the testing skills.

Terminal — clone and start
git clone https://github.com/rr-sairohith-vennu/rakcal cd rakcal git checkout workshop-start npm install npm run dev
App is running at http://localhost:3000 — open it in the browser to confirm before continuing.

Install Playwright MCP if you haven't already:

Terminal
claude mcp add playwright -- npx @playwright/mcp@latest

Restart Claude Code after running this. Then open the project in Claude Code and continue.

Model: Use Sonnet 4.6 at 200K context. Don't switch to 1M — it produces worse results for this workflow.
Step 0.5 Gap Analysis

Understand What's Missing

Before writing any tests, understand what the existing codebase is missing. This is the starting point of the testing workflow.

0.5 Gap Analysis →1 spec-tests →2 plan →3 build-tests →4 spec-ui-e2e →5 build-playwright →6 fix + run
The gap analysis report is already pre-generated in the repo at .forge/efforts/rakcal/validation/report.md — read it before running anything.
Claude Code — ask Claude to summarise the gaps
Read .forge/efforts/rakcal/validation/report.md and summarise what test coverage is missing.
What to look for
Which BRs have no test scenario
Which API endpoints have no contract test
Which UI states have no Playwright spec
Why it matters
forge:spec-tests uses these gaps to know what scenarios to generate. Understanding the gap first helps you evaluate whether the output is complete.
Step 1 forge:spec-tests — ~5 min

Generate the Test Suite

Reads the requirements and generates BDD scenarios for every testable behaviour. No test code is written yet — this is the specification.

0.5 Gap Analysis →1 spec-tests →2 plan →3 build-tests →4 spec-ui-e2e →5 build-playwright →6 fix + run
Claude Code
/forge:spec-tests --type e2e
This generates e2e-test-suite.md and ui-e2e-test-suite.md under .forge/efforts/rakcal/spec/test/ — markdown files with numbered BDD scenarios derived from the PRD requirements.
Expected scenarios from the PRD
› User browses past months and sees historical bonus events
› User views upcoming events for next 30 days
› User filters calendar by category — sees only relevant events
› User sets email reminder — fires 24hr before event start
› Mobile: tap calendar day → merchant names + rates visible
Note: spec-tests also generates UI E2E scenarios. Don't run without --type e2e during the workshop — full run takes longer and includes integration/contract suites we're not covering today.
⚠️ Ignore the "Next steps" suggestion from forge:spec-tests. It suggests running forge:spec-ui-e2e directly — but follow this guide's order instead. Step 2 is /forge:plan, not forge:spec-ui-e2e. The plan step adds the test implementation tasks that forge:build-tests needs.
Step 2 forge:plan — ~2 min

Add Test Tasks to the Plan

Reads the generated test suites and adds implementation tasks to the plan so forge:build-tests knows what to implement.

0.5 Gap →1 spec-tests →2 plan →3 build-tests →4 spec-ui-e2e →5 build-playwright →6 fix + run
Claude Code
/forge:plan
Look for two new tasks added to plan/tasks.md:
TASK-10 — implement E2E tests (backend API)
TASK-11 — implement UI E2E tests (Playwright)
These task IDs are what forge:build-tests uses to know which test suite to implement. If you don't see them, re-run forge:plan.
Step 3 forge:build-tests — ~8 min

Build the E2E Test Code

Reads the BDD scenarios, writes executable test code, runs them, and fixes any failures automatically. This is the backend API test.

1 spec-tests →2 plan →3 build-tests →4 spec-ui-e2e →5 build-playwright →6 fix + run
Claude Code
/forge:build-tests --type e2e-test
Watch for permission prompts. When Playwright MCP asks for permission to interact with the browser, answer Yes (for this session). Don't click away — the skill is waiting for you.
While it runs (~8 min), open the test suite file it's working from:
.forge/efforts/rakcal/spec/test/e2e-test-suite.md
Read through the scenarios — understand what each one is asserting and why.
What it produces
Test files in tests/ directory. Each BDD scenario becomes one test function. Runs headless first, fixes failures up to 3 cycles.
If it fails after 3 cycles
It will stop and tell you the last error. Read it carefully — usually a missing endpoint or a selector that changed. Don't re-run blindly.
Step 4 forge:spec-ui-e2e — ~2 min

Generate Gherkin Feature Files

Converts the ui-e2e-test-suite.md into Gherkin .feature files — the input format for forge:build-playwright-tests.

2 plan →3 build-tests →4 spec-ui-e2e →5 build-playwright →6 fix + run
Claude Code
/forge:spec-ui-e2e
Answer the prompts
› Region → us
› Feature area → rakcal
Creates features/us/rakcal/ with one .feature file per UI surface: calendar-view.feature, event-detail.feature, reminders.feature, filters.feature
Open one of the .feature files after it completes. Each scenario is in Gherkin format: Given / When / Then. This is exactly what forge:build-playwright-tests will turn into runnable Playwright code.
Step 5 forge:build-playwright-tests — ~15 min

Build Playwright UI Tests

Opens a real browser, discovers DOM selectors by interacting with the live app, writes .spec.ts files, runs them, and fixes failures.

3 build-tests →4 spec-ui-e2e →5 build-playwright →6 fix + run
Claude Code
/forge:build-playwright-tests us
First run only: If Playwright MCP wasn't installed yet, it installs now and asks you to restart Claude Code. After restarting, re-run the exact same command — it resumes from where it stopped.
While it runs — this is the interesting part. The skill navigates to your running app (localhost:3000), queries the DOM to find real selectors, then writes test code based on what it actually finds. Watch the browser open and interact. You don't need to do anything — just observe.
Output
tests/bdd/rakcal/
calendar-view.spec.ts
event-detail.spec.ts
reminders.spec.ts
filters.spec.ts
What it checks
Runs tests after writing. Fixes failing selectors up to 3 times. Runs validate.js at the end to confirm feature files are fully covered.
Step 6 Fix + Run Tests

Fix Failures & Run in Headed Mode

If tests are failing, fix them. Then run in headed mode so you can see the browser interact with the calendar.

4 spec-ui-e2e →5 build-playwright →6 fix + run

If tests are still failing after Step 5:

Fix failing tests
/forge:build-playwright-tests us --fix

Once tests pass — run in headed slow mode:

Claude Code — type this as a message
Run the Playwright tests in headed slow mode so I can see the browser

Or run directly from terminal:

Terminal
npx playwright test tests/bdd/rakcal/ --project=local-anonymous --headed --slow-mo=800
You should see the browser open, navigate to the calendar, click days, open event details, set a reminder, apply filters — all automatically. Each step corresponds to a scenario from the BDD feature files.
Help Common problems

Troubleshooting

Things that commonly go wrong and how to fix them.

  • Playwright MCP not found — Run claude mcp add playwright -- npx @playwright/mcp@latest then restart Claude Code. Re-run the command after restart.
  • Tests fail after 3 cycles — Don't re-run blindly. Read the last error message. Usually a selector changed or an endpoint isn't running. Fix the root cause first.
  • forge:build-tests finds no tasks — You skipped forge:plan or it didn't add the test tasks. Re-run /forge:plan and look for TASK-10 and TASK-11.
  • forge:spec-ui-e2e asks for region — Answer us. It uses this to place .feature files in features/us/.
  • Context window filling up — Run /compact in Claude Code. Then resume the skill you were running. Stay on 200K model.
  • App not running — Make sure npm run dev is running in a separate terminal before running any test skill. Tests hit localhost:3000.
  • Permission prompts keep appearing — When Playwright MCP asks, choose "Yes (for this session)" to allow all actions without being asked again.
  • forge:validate says FAIL — A requirement has no covering spec. Run the spec skill for the missing domain (/forge:spec-api or /forge:spec-storage) then re-validate.
